# Аудит стабильности Proxy Manager

Дата: 5 ноября 2026 года. Проверен исходный код приложения и собранное расширение в отдельном профиле Chromium. Пользовательские профили браузера и реальные учётные данные не использовались.

## Найденные причины

| Проблема                   | Прежнее поведение                                                                                | Исправление                                                                                                  |
| -------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| Ложное подключение         | Переключатель `isEnabled` одновременно считался подтверждением соединения                        | Отдельное наблюдаемое состояние; успех только после проверки маршрута и ответа с валидным exit IP            |
| Конфликт расширений        | `settings.set()` и запись в storage не подтверждали, кто управляет настройками                   | Проверка `levelOfControl` и фактической конфигурации до и после сетевого запроса; события изменения настроек |
| Возврат управления         | При освобождении конкурирующего расширения возвращались прежние настройки без повторной проверки | Повторная проверка даже при совпадении вернувшейся конфигурации                                              |
| Остановка MV3 worker       | Инициализация выполнялась только по startup/install                                              | Инициализация при каждом запуске worker; восстановление периодического alarm                                 |
| Потеря доступности         | После включения не было постоянной проверки                                                      | Проверка раз в минуту, после старта и по запросу; обработка proxy/SOCKS ошибок реального трафика             |
| Гонки                      | Старый ответ мог относиться к уже изменённому профилю                                            | Единая очередь операций, отмена проверок, revision и SHA-256 отпечаток параметров маршрута                   |
| Неверный пароль            | После второго challenge попытка удалялась из Set: третий challenge мог отправить пароль снова    | Ограничение по requestId и адресу прокси, отмена повторного challenge, очистка после завершения запроса      |
| Временный тест             | После падения worker мог остаться тестовый PAC                                                   | Журнал до изменения настроек; восстановление исходной конфигурации либо очистка собственной настройки        |
| Подмена маршрута теста     | Не проверялось, сохранилось ли управление после set и после ответа                               | Проверяется владелец и точный PAC; `mandatory: true`; нет DIRECT fallback для кандидата                      |
| Bypass                     | PAC понимал только hostname wildcard; терялись схемы, порты и CIDR                               | Поддерживаемые правила компилируются в PAC; неподдерживаемый маршрут отклоняется                             |
| Некорректный ответ сервиса | Регулярное выражение принимало `face`, `1.2.3`, `999.999.999.999` за IP                          | Строгая проверка IPv4 и IPv6, проверка страны; редиректы не принимаются                                      |
| Устаревший popup           | Асинхронные чтения могли завершиться в обратном порядке                                          | Подписка до первого чтения, отсечение устаревших ответов и освобождение подписок                             |

## Контракт соединения

`isEnabled` — желание пользователя использовать выбранный профиль. Оно сохраняется при недоступности сервера, чтобы тот же маршрут мог восстановиться. Само по себе оно не означает «подключено».

`chrome.storage.session.connection` — подтверждённый результат: `disconnected`, `connecting`, `connected`, `error` или `conflict`, время проверки, IP и задержка. Отпечаток включает адрес, протокол, credentials и bypass, но хранится в виде SHA-256; пароль в диагностику не записывается. Имя и иконка не меняют маршрут.

Зелёный статус требует совпадения профиля, контроля Chrome и сетевого подтверждения. Popup перестаёт считать результат свежим через 90 секунд, даже если worker не работает. Периодические проверки не переписывают уже применённую конфигурацию. Смена профиля и выключение отменяют текущую проверку; неверный результат не включает другой профиль автоматически.

После ошибки прокси не заменяется прямым соединением. Явные bypass-правила продолжают действовать. Переключатель показывает выбранный режим, а точка соединения и ON — только подтверждённое соединение.

## Передача управления

Chrome отдаёт приоритет последнему установленному расширению; политика организации имеет более высокий приоритет. Повторный `settings.set()` этого не обходит.

Кнопка разрешения конфликта запрашивает необязательное разрешение `management`. Показываются включённые расширения с разрешением `proxy`: API не сообщает точный ID владельца. Пользователь отдельно выбирает, какое отключить. Worker повторно проверяет текущий конфликт, наличие разрешения, ID, enabled/proxy и `mayDisable`, затем отключает только выбранный объект. При исчезновении конфликта выбранный включённый профиль проверяется снова.

Выключенные таким способом расширения остаются выключенными; включить их можно в `chrome://extensions`. Администраторскую политику приложение не меняет.

## Границы проверки

- Кандидат тестируется через временный обязательный PAC только для четырёх диагностических хостов. Остальной трафик сохраняет поддерживаемый исходный direct/fixed маршрут, включая bypass.
- System/WPAD, remote/произвольный PAC, несколько разных proxy rules и некоторые сложные bypass нельзя точно воспроизвести внутри такого PAC. Отдельный тест отклоняется без изменения настроек. Можно сохранить профиль и включить: проверка активного fixed-маршрута не использует временный PAC.
- Активная проверка исключает диагностические адреса, попавшие в bypass. Если исключены все адреса, состояние не подтверждается прямым ответом.
- Проверки используют внешние IP-сервисы; недоступность всех сервисов означает «не подтверждено», даже если часть других сайтов работает. Успех одного сервиса не гарантирует доступность каждого сайта.
- Alarms могут задерживаться при сне/нагрузке; это не непрерывный сетевой монитор. Нельзя обещать нулевое время обнаружения отказа.
- Проверяется regular scope. Настройки incognito, заданные отдельно другим расширением, этим статусом не подтверждаются. Это расширение Chrome, не системный VPN и не перехват UDP/WebRTC или трафика других приложений.
- Кэш HTTP proxy credentials управляется Chrome; расширение не удаляет пользовательские пароли и не очищает глобальные данные браузера.
- Реальные серверы пользователя и его остальные расширения требуют проверки после обновления.
